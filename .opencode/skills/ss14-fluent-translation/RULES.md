# Правила перевода SS14 Fluent

Эти правила применяются к переводу изменённых значений Fluent (`.ftl`) с английского на русский.

## 1. Общие правила

- Не добавляй сведения, которых нет в оригинале.
- Сохраняй смысл, тон, эмоции, юмор, сарказм и степень формальности.
- Если буквальный перевод искажает смысл, используй естественный русский вариант без добавления нового смысла.

## 2. Fluent-синтаксис и форматирование

Не изменяй:

- ключи сообщений;
- имена атрибутов и вариантов;
- структуру Fluent-сообщений;
- переменные и placeable-конструкции;
- имена функций, их аргументы и порядок аргументов;
- теги и параметры тегов;
- технические символы, разделители и экранирование.

Сохраняй порядок строк, отступы и переносы строк. Не выполняй переформатирование и не добавляй пустые строки, пробелы, разделители или Markdown.

Комментарии, начинающиеся с `#`, сохраняй без изменений и не переводи.

Атрибуты (`.desc`, `.suffix` и т.п.) переводятся по тем же правилам, что и значение самого ключа.

Если тег содержит переводимый текст, переводи только текст внутри тега:

```text
[bold]Warning[/bold] -> [bold]Предупреждение[/bold]
```

### Функции

Исключение из правила «не изменяй имена функций» (см. раздел 2) — только `THE($item)`, замени на `{$item}`.

Другие функции Fluent (`CAPITALIZE`, `GENDER`, `INDEFINITE`, `SUBJECT`, `OBJECT`, `POSS-ADJ` и т.п.) не трогай: сохраняй имя функции и аргументы без изменений, переводи только текст вне вызова функции.

```text
{THE($item)} -> {$item}
```

## 3. Регистр

Всегда сохраняй регистр оригинала — без исключений, вне зависимости от того, меняется ли число слов при переводе.

- Если оригинал целиком в ALL CAPS — перевод целиком в ALL CAPS.
- Если в оригинале каждое слово с заглавной буквы (Title Case) — в переводе каждое слово тоже с заглавной буквы, даже если это не соответствует обычной русской орфографии.
- Если в оригинале только первое слово с заглавной буквы — в переводе только первое слово с заглавной.
- Если оригинал полностью в нижнем регистре — перевод полностью в нижнем регистре.
- Определяй паттерн по оригиналу как единому целому (а не слово-в-слово), затем применяй этот же паттерн к переводу целиком — это снимает проблему несовпадающего числа слов.

Примеры:

```text
Security Officer -> Офицер Службы Безопасности
NANOTRASEN -> НАНОТРЕЙЗЕН
security officer -> офицер службы безопасности
EXAMPLE EXAMPLE -> ПРИМЕР ПРИМЕР
```

## 4. Числа и технические значения

Сохраняй без изменений целые и десятичные числа, отрицательные значения, проценты, диапазоны и десятичные разделители. Не заменяй точку на запятую:

```text
12.5% -> 12.5%
```

## 5. Пунктуация

- Не используй длинное тире `—`. Используй `-` (дефис) или `–` (среднее тире) в зависимости от контекста.
- Обычные двойные кавычки из текста переводи в русские кавычки «».
- Не изменяй кавычки и символы, являющиеся частью технических конструкций.

## 6. Обращение и терминология

- По умолчанию обращайся к игроку на «вы».
- «Ты» используй в репликах персонажей только если фамильярность или неформальность явно следует из контекста.
- Обязательные термины бери из `.opencode/docs/GLOSSARY.md`.
- Используй один термин единообразно в пределах изменяемого текста.
- Допускай грамматическое склонение закреплённого термина, если этого требует русская грамматика, но не заменяй термин синонимом.
- Если в изменениях встречаются специфичные для SS14 термины, которых нет в глоссарии, укажи их отдельным списком на этапе планирования и предложи варианты перевода.
- Не добавляй новые термины в `.opencode/docs/GLOSSARY.md` без явного подтверждения пользователя.

## 7. Множественное число

В английском Fluent-селекторе обычно два варианта (`one`, `other`), в русском грамматически необходимо три (`one`, `few`, `many`). Добавление недостающих вариантов `few`/`many` в уже существующий селектор не считается добавлением нового ключа и разрешено без отдельного согласования.

```text
{ $count ->
    [one] { $count } item
   *[other] { $count } items
}
->
{ $count ->
    [one] { $count } предмет
    [few] { $count } предмета
   *[many] { $count } предметов
}
```
